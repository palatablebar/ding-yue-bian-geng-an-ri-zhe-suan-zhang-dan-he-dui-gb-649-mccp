# 定义契约 subbill

## 金额

- 单位：人民币元，最小刻度 0.01（一分）。
- 内部类型：`Decimal`（decimal 上下文 34 位），入库精度 8 位小数；记账值一律整数「分」。
- 禁止：float 参与运算或累加；JSON 里的金额只出现两位小数字符串或整数分。
- 舍入：只在记账时量化到分，四舍五入（ROUND_HALF_UP）；一张账单内多分量的尾差用最大余额法分配。

## 月价与日价

- 月价是订阅当前套餐的整月价格，允许输入三位小数（会标 `R_PRICE_PRECISION`），不提前取舍。
- 日价 = 月价 ÷ 该计费期间的实际天数，不单独四舍五入。
- 一段区间的金额 = 月价 × 段天数 ÷ 期间天数，先乘后除，避免逐日累加放大误差。

## 时间

- 存储：全部 UTC（ISO 8601 带 `+00:00`）。
- 展示：固定 `Asia/Shanghai`；账单页与清单页都标注时区。
- 计费日边界：取订阅自身时区的本地日 0 点。订阅时区缺省为 `Asia/Shanghai`。
- 生效时刻：先按字段自带的偏移（`Z`、`+08:00`、`+0800`）或时区名定位到 UTC；都没有时用订阅时区。
- 夏令时：本地时刻出现两次时取较早一次并标 `R_DST_AMBIGUOUS`；本地时刻不存在时顺延到第一个合法时刻并标 `R_DST_GAP`。
- 整日生效：生效时刻不是本地 0 点时按当日 0 点取整，并标 `R_TIME_TRUNCATED`，原值保留在隔离区。

## 区间与天数

- 计费期间与分段一律半开区间 `[start, end)`：左闭右开，相邻段 `end` 等于下一段 `start`。
- 天数 = 本地日历日差（`end - start` 的天数），不是 24 小时整除。
- 闰年：2 月 29 日算一天；2028-02 期间 29 天。判断闰日看 `[start, end)` 是否覆盖 2 月 29 日。
- 期间天数 = 计费天数 + 免费/暂停天数，三者对账必须相等。

## 状态与费率

| 状态 | 含义 | 费率 |
|---|---|---|
| `active` | 生效中 | 正常月价 |
| `paused` | 暂停 | 0，天数计入免费 |
| `trial` | 试用 | 0，天数计入免费 |
| `cancelled` | 已取消 | 0，天数计入免费 |

变更类型：`升配/升级 → upgrade`、`降配/降级 → downgrade`、`暂停/挂起 → pause`、`恢复 → resume`、`取消/解约 → cancel`。
暂停与取消的新月价一律按 0 处理；恢复未填新月价时沿用变更前的月价。

## 去重键

- 订阅：业务键 `订阅号`。两行取值完全相同 → 丢弃后行并记 `R_DUP_SUB_ROW`（info）；取值不同 → 保留行号小的，另一行进隔离区并记 `R_DUP_SUB_KEY`（error）。
- 变更：业务键 `变更号`；同一订阅同一本地日只允许一条生效，胜者按 `(生效时刻, 变更号)` 最小。
- 账单：`INV-<期间起年月>-<订阅号>`，一张订阅一个期间一张账单。

## 空值

- 三类语义分开：`null`（不可用）、空串/哨兵（缺失）、`0`（真值）。
- 哨兵清单集中在 `app/config.py` 的 `SENTINELS`：`-`、`--`、`/`、`N/A`、`未知`、`无`、`暂无`、`待定`、`不适用` 等。
- 月价缺失 → `R_PRICE_MISSING`（error，隔离）；月价为 0 → 合法金额。

## 空态

| 形态 | 原因码 | 结论 |
|---|---|---|
| 0 字节 | `R_EMPTY_FILE` | 没有数据行，整份文件不可用 |
| 只有表头 | `R_HEADER_ONLY` | 没有数据行，整份文件不可用 |
| 全是空行 | `R_BLANK_ROWS` | 没有可用数据行，整份文件不可用 |
| 有数据行 + 部分空行 | `R_BLANK_ROWS`（warn） | 空行计数，不阻断其余行 |

## 原因码级别

- `error`：行不可用，进隔离区，计数进行数账的「隔离行」。
- `warn`：行可用但需要人工复核（迟到、同日多次、夏令时、期间外变更）。
- `info`：已自动归一（千分位、全角、三位小数、尾差补差）。

## 运行清单

- `run_id`：`SB-<本地时间戳>-<4 位随机>`，右侧两位 `check_digit` 为 mod-97 校验位；终止结算批次前缀为 `ST`。
- `batch_key`：规则版本 + 两份输入 sha256 的摘要；同 key 重跑复用同一批次。
- 清单记录：输入文件名、字节数、编码、行数、sha256、参数、阶段计数、四本账结论、合计、耗时。

## 年度合同终止结算

### 口径：承诺不可撤销，未履行服务作废

年度合同签的是整份承诺 `C`。中途终止只改变服务截止日，不改变应收本金：

- 运营口径「未履行部分作废」＝ 不再提供服务，不是放弃收款；
- 财务口径「未履行承诺本期一次结清」＝ `C` 中尚未开票的部分本期出账；
- 两者不矛盾：作废的是服务义务，结清的是合同债权。

```
最终应收       = 合同承诺 C
本期终止结算   = C − Σ已出账单 I
恒等式         = 已出账单 + 本期结算 = 最终应收 = C
```

已出月份逐张冲抵（`I₁ … Iₙ` 各自一行），所以不存在重复收费；
剩余金额不再按天折算，避免「缩小到停机日」和「扩到整份合同」两套算法并存。

### 停机日

- 停机日含当天服务：`已服务 = [合同起, 停机日 + 1天)`，`未履行 = [停机日 + 1天, 合同止)`。
- 边界：`合同起 <= 停机日 < 合同止`。
  - 停机日 = 合同起：一天都没服务，仍按承诺结清。
  - 停机日 = 合同止：服务到期，不需要终止结算，报 `R_TERMINATION_AFTER_END`。
- 天数只用来解释「承诺里有多少天没服务」，不参与金额二次折算。

### 结算单

- 结算单号 `ST-<停机年月>-<合同号>`：同一合同同一停机月稳定可复算。
- 终止指令幂等键：`CMD:<合同号>:<终止指令号>`，缺指令号时 `KEY:<合同号>:<停机日>`。
- 一份合同只能有一张生效结算单；同一合同多条指令按 `(停机日, 指令键, 行号)` 最小确定性取一条，
  其余留档并标 `R_TERMINATION_DUP`。
- 发布以「版本」为单位：页面、CSV、清单都读 `active` 版本，不各自重算。
  新版本在同一事务里替换旧版本；撤下终止指令时旧版本同事务失效。

### 采信与隔离

- 合同表：一行 = 合同定义 + 可选终止指令。合同定义冲突（承诺或期间不同）保留行号小的，另一行进隔离区。
- 已出账单表：账期必须落在合同内；账期重叠即重复收费，**重叠后到的那张不进冲抵**并进隔离区。
- 合计超过承诺（`C − ΣI < 0`）不拒绝，结算单按退款处理并标 `R_ISSUED_OVER_COMMITMENT`。
- 失败批次 `status=failed` 留档可查，不参与 `batch_key` 复用，也不改动任何已发布版本。

### 四本账

| 账 | 左 | 右 |
|---|---|---|
| 结算单账 | 结算单数 | 唯一终止指令数 |
| 承诺账 | 合同承诺合计 | 已出账单合计 + 本期结算合计 |
| 已出账单冲抵账 | 已出账单合计 | 承诺 − 本期结算 |
| 终止指令账 | 结算单数 | 合同数 |
